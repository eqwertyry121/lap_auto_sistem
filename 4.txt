## 🛠 1. Исправление конфликта в ТЗ (Авто-отклики vs Ручная переписка)

### 📌 Текст правки для Qwen:

> **ИЗМЕНЕНИЕ В SCOPE (ВАЖНО):**
> 
> Исключить из текущего релиза (MVP) модули автоматической отправки сообщений продавцу на KP (`KP Reply Worker`, `WAITING_SELLER_REPLY` и авторизованные POST-запросы).
> 
> **Текущий пайплайн системы:**
> 
> 1. Сбор объявлений $\rightarrow$ 2. Дедупликация в DB $\rightarrow$ 3. Детализация `/eds/{id}` $\rightarrow$ 4. Анализ Gemini (Text + Vision) $\rightarrow$ 5. **Мгновенное уведомление в Telegram (Alert / Need Check)**.
>     
> 
> Все коммуникации с продавцом выполняются пользователем **вручную** по клику на ссылку из Telegram-сообщения.

## 📊 2. Архитектурная правка: PostgreSQL vs Google Sheets API

### 💡 В чем фундаментальная проблема:

Google Sheets API имеет лимит **100 запросов за 100 секунд**. Если скрипт будет на каждое новое объявление делать `AppendRow()`, то при очередном скачке активности на KP ты поймаешь `HTTP 429 Too Many Requests`, и Sheets заблокирует бота.

### 📌 Текст правки для Qwen:

> **АРХИТЕКТУРА ХРАНЕНИЯ ДАННЫХ И РЫНОЧНОЙ АНАЛИТИКИ:**
> 
> 1. **PostgreSQL — Единственный источник правды (SSOT):**
>     
>     - Все входящие объявления (даже оверпрайс и хлам) мгновенно записываются в таблицу `market_listings` в Postgres.
>         
>     - Дедупликация (`ad_id`) и кэш рыночных цен работают **исключительно через PostgreSQL**.
>         
> 2. **Асинхронный экспортер в Google Sheets (`exporter/sheets.go`):**
>     
>     - Запрещено делать прямые запросы к Google Sheets API при парсинге лота!
>         
>     - Выгрузка в Google Sheets происходит **фоновым воркером 1 раз в 30–60 минут пачкой (Batch Update)**.
>         
>     - Воркер делает один SQL-запрос `SELECT * FROM market_listings WHERE synced_to_sheets = false`, формирует пачку строк и отправляет её в Google Sheets **одним вызовом API (`AppendValues`)**, после чего меняет статус в БД.
>         

## 🧠 4. Подробный разбор Gemini Vision: Скорость и Процессоры

### ⚡ Проблема А: Задержка и блокировка (Latency)

Если на KP вылетает 5 новых ноутбуков одновременно, а Gemini обрабатывает один лот за 4 секунды, то при последовательном вызове последний ноутбук будет проанализирован через **20 секунд**. В арбитраже это вечность.

### 📌 Решение в Go для Qwen:

> **Параллельная оценка (Worker Pool / Goroutines):**
> 
> Анализ через Gemini **обязательно** должен запускаться в параллельных горутинах с лимитером (например, не более 5 одновременных запросов к Gemini API через `sync.WaitGroup` или семафор):
> 
> Go
> 
> ```
> // Пример концепта для Qwen:
> semaphore := make(chan struct{}, 5) // Макс 5 параллельных AI-оценок
> for _, ad := range newAds {
>     wg.Add(1)
>     go func(a Ad) {
>         defer wg.Done()
>         semaphore <- struct{}{}
>         evaluator.AnalyzeWithGemini(a)
>         <-semaphore
>     }(ad)
> }
> ```

### 🔍 Проблема Б: Галлюцинации поколений CPU (Цены на i5)

Главный капкан на сербском рынке: продавец пишет «Продам HP i5 8GB».

- **i5 4-го поколения (2014 год):** реальная цена €50.
    
- **i5 11-го поколения (2021 год):** реальная цена €250.
    

Если Gemini «увидит» слово `i5` за €80 и подумает, что это свежий проц, она выдаст `is_deal: true`, хотя это старое ведро.

### 📌 Строгие правила для Промпта Gemini (Вписать в ТЗ):

> **ТРЕБОВАНИЯ К SYSTEM PROMPT ДЛЯ GEMINI API:**
> 
> В системный промпт Gemini Vision зашить **жесткие правила квалификации процессоров**:
> 
> 1. **Точное поколение:** Gemini НЕ имеет права считать маржинальность, если не определена точная модель процессора (например, `i5-1135G7` или `Ryzen 5 4600H`).
>     
> 2. **Поиск поколений на фото:** Gemini должна детально искать стикеры `Intel Core` / `AMD Ryzen` на корпусе и шильдики на дне ноутбука.
>     
>     - Серый/Черный стикер Intel $\rightarrow$ 10-14 поколение.
>         
>     - Синий стикер Intel $\rightarrow$ 4-9 поколение.
>         
> 3. **Неизвестное поколение (Fallback):** Если в тексте написано просто "i5", а на фото стикер не читается:
>     
>     - Запрещено ставить `is_deal: true`.
>         
>     - Обязательно отдавать JSON:
>         
>         `{ "is_deal": false, "need_check": true, "reason": "Неизвестно поколение CPU (указано просто i5)" }`.
>         
>     - Бот должен отправлять такой лот в Telegram со статусом `⚠️ NEED CHECK`, чтобы ты сам глянул на него глазом.
>
