> Обновлено: 2026-08-06 21:00. Проект: KP Laptop Arbitrage Bot («The Bot God of Laptop»).

## Что это

Go-бот ищет недооценённые ноутбуки на KupujemProdajem (Сербия): мониторинг →
оценка Gemini → алерты в Telegram. С 2026-08-05 (вечер) продукт сфокусирован:
**только ноутбуки с дискретной видеокартой**, MacBook забанены. Цель — «лучшие
из лучших по лучшим ценам»: алерт = ноутбук в НИЗУ рынка, с которого перекуп
выходит в плюс.

## Политики v6 — «лучшие из лучших по низу рынка» (2026-08-05, ночь)

> Пересмотр по обратной связи перекупа: убраны «прилагательные» и лишние CHECK.
> Алерт приходит только на реальные сделки в низу рынка, всё остальное — тихо.

- **Убран гейт «есть мощнее за те деньги»**: он отсекал весь низ рынка
  цепочкой «за €300 есть за €310, за €310 — за €320…». Теперь «шаг вверх»
  показывается в алерте ЦИФРАМИ и ничего не отклоняет.
- **Композитная мощность = CPU + GPU** (`Lot.Composite`) — единая метрика
  «мощнее/слабее». Кейс Alienware M17 R3 (i7-10750H + RTX 2070 Super): по
  сумме баллов он мощнее «альтернатив» на RTX 3050 — старый гейт «мощнее CPU»
  его ложно браковал.
- **«Шаг вверх» = `BestStepUp`**: среди ноутбуков мощнее (CPU+GPU) И дороже
  кандидата берётся тот, у кого минимальна ЦЕНА ЗА ЕДИНИЦУ ПРИРОСТА мощности
  (Δцена/Δбаллы). Обезвреживает ловушку «+10 баллов за +€1» против
  «+1000 баллов за +€1» — метрика выберет второе. Показывается в алерте.
- **Некритичные дефекты не блокируют**: `JunkDefect` → алерт с пометкой
  «✅ Хороший, но с нюансом: …». Блокирует только `PARTS_ONLY` (труп/запчасти).
  `BROKEN_UNCERTAIN` → CHECK.
- **Алерт без «прибыли €X», только цифры**: средняя цена на такие, баллы
  кандидата (CPU/GPU/сумма + баллов/€1000), отклонение, «шаг вверх» (цена,
  прирост баллов, € за +1000 баллов), нюанс.
- **Вердикты v6:** 💎 DIAMOND (низ рынка ≤ DIAMOND_DEV_PCT, n≥minN или веб);
  💎❓ SUSPECT (< SUSPECT_DEV_PCT или молодой продавец на скидке);
  ⚠️ CHECK (CPU вне эталона / низкоуверенный веб / малая группа / UNCERTAIN);
  всё остальное (FAIR/EXPENSIVE/NO_MARKET/NO_GPU/BAN/SHOP/JUNK/SANITY) — ТИХО.

## Выполнено в сессию 2026-08-05 (вечер, №2): PLAN_v5 — ФОКУС НА dGPU

> Пользователь-перепродавец берёт только ноутбуки с CPU+GPU (дискретной
> видеокартой), MacBook не берёт совсем. Пример плохого алерта: офисный
> EliteBook на Ultra 5 (без dGPU) сравнился с игровыми i9 — медиана K2
> смешивала сегменты, гейт «мощнее за те же деньги» смотрел только CPU.

- **Фаза A — бан MacBook + dGPU-гейт:** `filters.IsBannedModel` (нормализованный
  поиск маркеров из env `BANNED_MODELS`, по умолчанию `macbook`); бан срабатывает
  в `main.go pollOnce` ДО запроса `/eds/` (экономия лимитов KP, статус
  `SKIPPED_BAN`) и дублируется в воронке (код `BAN_MAC`); dGPU-гейт после L3:
  нет дискретной графики → тихий `NO_GPU` (env `REQUIRE_DGPU`, по умолчанию 1).
  Имя распознанной dGPU хранится даже без балла hw.db (присутствие важнее балла).
- **Фаза B — рынок dGPU + гейты цена/качество:**
  - `pricing.Options.DGPUOnly`: статистический пул только из dGPU-лотов;
  - ключи групп K0/K1/K2 в dGPU-режиме **с GPU-измерением на всех уровнях**
    (нормализация `hw.Key`) — игровые и офисные больше не смешиваются;
    старый (полный) рынок для cmd/analyze не изменён;
  - новые `StrongerCPUForBudget`/`StrongerGPUForBudget`: коридор ±`PRICE_BAND_PCT`
    (10%), «мощнее» ≥ +`STRONGER_PCT`% баллов (10; пользовательский диапазон 5–10);
    без балла GPU в эталоне GPU-гейт честно пропускается;
  - `decideL5` переписан (PLAN_v5 §3.5–3.7): дороже рынка +`MARKET_TOL_PCT` (5%)
    → EXPENSIVE тихо; есть мощнее CPU ИЛИ GPU за эти деньги → CHECK с
    альтернативами по двум осям; ничего мощнее нет → SUSPECT (<−40%) /
    DIAMOND (≤−15%) / **новый код GOOD** (рыночная цена, лучший по цена/качество);
  - алерты-досье (`valueAlertText`/`checkAlertText`): конфигурация с
    бенчмарк-баллами CPU/GPU, источник цены (медиана n=… / интернет-оценка),
    блок «за эти деньги есть мощнее» отдельно по CPU и GPU.
- **Фаза C — полнота распознавания:**
  - ступень **L3.4 «интернет: модель→железо»** (`vision/model_specs.go`,
    Gemini+Google Search): модель ноутбука известна, но CPU/GPU не найдены →
    поиск официальных спеков модели в интернете; результат валидируется hw.db;
  - `specs.ExtractGPU` расширен: RTX A-series, Quadro, T-series ≥1000
    (защита от ThinkPad T4xx), Radeon Pro, Intel Arc + регрессионные тесты.
- Тесты: бан-функции, decideBan, dGPU-пул, GPU-измерение медиан, оба гейта,
  новая таблица decideL5 (включая GOOD/EXPENSIVE/веб-ветки), новые GPU-паттерны.
  Все зелёные: `go build && go vet && go test ./...`.

- **Фаза 4 — воронка L0–L5 в БОЕВОМ режиме живого бота (2026-08-05):**
  L0 sanity цены/обмена → детали → L1 магазины (метки KP + реестр sellers +
  маркеры) → L2 хлам → L3 конфигурация (regex → Gemini-текст → Gemini-фото,
  Gemini дёргается ТОЛЬКО на нераспознанные) → L4 медианы конфигураций
  (leave-one-out, `pricing`) → L5 детерминированный вердикт: 💎 DIAMOND /
  💎❓ SUSPECT / ⚠️ CHECK / ✅ FAIR / ❌ EXPENSIVE / 👀 MANUAL. Алерт несёт
  конфигурацию, медиану (n), отклонение и альтернативы. Аудит в
  `market_listings` (verdict_code/deviation/group_n/alternatives), счётчики
  в `funnel_stats`. Пороги — env: DIAMOND_DEV_PCT=−15, SUSPECT_DEV_PCT=−40,
  DIAMOND_MIN_N=5; теневой режим — FUNNEL_SHADOW=1 (аудит без алертов).
  Рыночная модель обновляется раз в 6ч (MARKET_REFRESH_MIN), курс живой.
- **Пульт управления в Telegram (упрощён до трёх кнопок):** ▶️ Старт /
  ⏹ Стоп / 🩺 Статус. Стоп приостанавливает поллинг и воронку (процесс
  жив, пульт и watchdog продолжают работать, heartbeat пишет «paused»),
  Старт возобновляет. Слушает getUpdates, команды принимает только из
  TELEGRAM_CHAT_ID. Открыть: `/panel` или любое сообщение боту.
  (Прочие CLI-команды — в терминале, список ниже.)
- **Решение по L1 (2026-08-05, по требованию пользователя):** фильтр
  магазинов детектит ТОЛЬКО по тексту описания. Метки интерфейса KP
  («Trgovac»=is_trader, «KP Izlog»=kp_izlog) и поведенческие подсчёты
  (число лотов, возраст аккаунта) НЕ режут лот. Из словаря маркеров убраны
  слова-элементы интерфейса («svi oglasi», «kp izlog»). Остались только
  содержательные слова описания (garancija, više modela, na stanju, faktur,
  dostava širom Srbije, saobražnost, maloprodaja/veleprodaja и пр.) +
  структура прайс-листа (#NN-… / таблица «| … €»).
  Примечание: в медианах `pricing` магазинные лоты по-прежнему
  исключаются по is_trader/kp_izlog — это нужно для чистоты цены, а не для
  среза алертов; при желании отключается отдельно.
- **Фаза 1 — веха 1000 описаний пройдена**; 598 битых строк вылечены
  (см. «мягкий антибот» ниже).
- **Фаза 4А — готова:** пакет `pricing` (робастные медианы K0→K2,
  гедоническая OLS с честным отказом при коллинеарности/нулевой дисперсии,
  альтернативы A1/A2/A3, живой курс валют). Разведка на данных:
  `go run ./cmd/analyze -pricing` — покрытие пула медианами ~94%,
  OLS пока Usable=false (N=0: верх выдачи весь магазинный, см. ниже).
- **Фаза 2/3 — КОД готов, калибровка ждёт данных:** пакет `filters`
  (L1: правила М1–М6; L2: PARTS_ONLY/DEFECT + ценовой кросс-чек),
  `cmd/analyze -markers` (частотный анализ когорт), `cmd/label`
  (экспорт/импорт золотой выборки), `cmd/filtertest` (precision/recall
  гейты), реестр `sellers` в research.db, миграции `user_id/view_count/
  is_renewed/snippet`, бэкфилл `go run ./cmd/research -search-refresh`.
  Единые словари хлама: research.classify использует filters.L2 (SSOT).
- **Фаза 5 — код готов (запуск ручной, по бюджету):** `cmd/gemini-enrich` —
  L3-ступень Gemini-текст для дорогих нераспознанных лотов, write-back в
  `research_specs.source='gemini-text'`, защита Gemini-строк от перезатирания
  regex-проходом (`-enrich` их не трогает).
- **Фаза 6 — готова:** курс RSD→EUR (open.er-api.com, кэш в `kv` 24ч,
  fallback 117.2; frankfurter RSD не отдаёт — проверено), JSONL-очередь
  алертов при сбое Telegram (`data/alert_queue.jsonl`, доотправка),
  планировщик Windows: «KPBot Watchdog» (10 мин), «KPBot Research Refresh»
  (вс 03:17), «KPBot HWDB Monthly» (1-е число 04:23).

## Ключевое наблюдение о данных (не забывать!)

Верх выдачи KP захвачен магазинами с автообновлением лотов: обход первых
~130 страниц почти целиком магазинный, когорта частников для частотного
анализа появится, когда докачка дойдёт до глубинных страниц (или после
полного рынка).

**Семантика метки Trgovac (установлено живьём 2026-08-06, см. починку выше):**
KP присылает объект `user.trader` ВСЕМ продавцам; магазин = `title:"Trgovac"`,
частник = `title:"Nije trgovac"`. Старые цифры «~50% Trgovac среди деталей»
были артефактом сломанного предиката. Сейчас частники с описаниями есть
(2269), OLS-модель обучена (N=315, R²=0.789, Usable=true) — уровень K3 в
иерархии медиан живой; `cmd/analyze -markers` может считать lift на реальных
когортах.

## Мягкий антибот KP (найдено и починено в эту сессию)

KP иногда отвечает на /eds/ кодом 200 с ПУСТЫМ info (без описания и
продавца). Старый код помечал такие строки OK навсегда — датасет был
загрязнён 598 такими строками. Теперь:
- research не помечает пустые ответы OK (статус ERROR → ретрай), а при
  каждом старте `healEmptyOK` возвращает старые битые строки в очередь;
- живой бот возвращает такой лот в очередь (delete + следующий цикл).

### Трассировка воронки («увидеть всё своими глазами»)

Каждый лот пишет полный след в `data/funnel_trace.log`: все шаги L0–L5,
точные запросы к Gemini (промпты) и сырые ответы, какие фото отправлялись,
что принял/отклонил эталон hw.db. Включено по умолчанию (FUNNEL_TRACE=0 —
выключить). Смотреть вживую:

```powershell
Get-Content D:\the_bot_god_of_laptop\data\funnel_trace.log -Wait -Tail 40 -Encoding UTF8
```

## Текущее состояние и следующий шаг

1. Воронка L0–L5 в боевом режиме + **интернет-ресерч L4.5**: магазины/хлам
   режутся до Gemini (нулевые токены на них), «алмазы» считаются
   детерминированно по медианам, а при их отсутствии — по интернет-оценке
   (Gemini + Google Search). Наблюдать за bot.log и funnel_trace.log: новые
   коды `L4_WEB_RESEARCH`, `MANUAL_ALERT`, вердикты с пометкой
   «интернет-оценка»; пороги — env-переменными без кода.
2. Докачка деталей продолжается фоном. Как появятся частники с описаниями —
   **калибровка Фазы 2**: `cmd/analyze -markers` → словарь `filters/markers.go`
   → `cmd/label -export-top/-export-random` → ручная разметка ~50 продавцов →
   `cmd/filtertest` (гейты recall ≥ 0.95 / precision ≥ 0.90) → ThresholdL1.
3. `cmd/gemini-enrich` запускать осознанно (бюджет Gemini), например
   `-budget 50` раз в пару дней.
4. Пульт в Telegram: `/panel` → кнопки ▶️ Старт / ⏹ Стоп / 🩺 Статус.
