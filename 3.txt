Я полностью разобрал архитектуру и задачу проекта. Это **высокоскоростной мониторинговый и арбитражный бот на Go (Golang)** для поиска выгодных ноутбуков на KupujemProdajem (KP) с автоматическим мультимодальным анализом через **Gemini Vision API**.

## 🏗 Архитектура и логика работы (Пайплайн)

Вся система делится на 5 четких шагов:

```
[1. Поиск (30-60с)] ──> [2. Проверка ID (DB/Redis)] ──> [3. Детализация (/eds/{id})]
                                                                │
                                                                ▼
[5. Уведомление в TG] <── (Если is_deal=true) ─── [4. Оценка (Gemini Vision)]
```

1. **Poller (`collector/poller.go`)**:
    
    - Раз в 30–60 секунд делает лёгкий запрос к Search API для получения списка из 30 последних объявлений.
        
    - Учитывает заголовки (`user-agent`, `x-kp-channel: mobile_web_react`) и ротирует User-Agent для защиты от блокировок и обработки HTTP 429.
        
2. **Deduplication (`storage/db.go`)**:
    
    - Быстро сверяет `ad_id` с базой (Redis/Postgres). Старые ID сбрасываются, новые идут дальше.
        
3. **Data Fetcher (`collector/fetcher.go` / `eds`)**:
    
    - Для каждого **нового** ID запрашивает детальную информацию по эндпоинту `/api/web/v1/eds/{ad_id}` (получает полное описание, все характеристики и HD-фотографии).
        
4. **AI Evaluator (`vision/evaluator.go`)**:
    
    - Отправляет в **Gemini Vision API** описание и первые 3–5 HD-картинок.
        
    - Нейросеть оценивает физическое состояние (царапины, битые пиксели, наклейки, повреждения корпуса), сопоставляет характеристики с ценой и отдаёт строгий JSON: `{ "is_deal": bool, "estimated_profit": float, "reason": "string", "specs": "string" }`
        
5. **Notifier (`notifier/telegram.go`)**:
    
    - Если Gemini отдаёт `is_deal: true`, бот формирует красивое сообщение в Telegram с выжимкой характеристик, аргументацией выгоды, маржой и Inline-кнопкой для быстрого перехода на KP.
        

## 🛠 Технические нюансы, которые я учел

- **Двухэтапный сбор (Optimization)**: Мы не дергаем тяжелый API деталей `/eds/{id}` для всех подряд объявлений — только для реально новых `ad_id`, что снижает нагрузку и риски бана от KP.
    
- **Структуры данных**: Модели Go разделены на результаты быстрого поиска (`SearchAd`) и глубокой детализации (`AdDetailResponse` + `PhotoDoc`).
    
- **Анализ мультимодального контента**: Gemini смотрит не только на текст продавца (где часто скрывают дефекты), но и на реальные фотографии лота.
